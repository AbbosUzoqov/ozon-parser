Лог подхода — как разрабатывался парсер
Итог: 5 подходов, 3 не сработали, 2 частично работали, финальный — рабочий

Попытка 1 — Playwright + селектор [data-sku]
Что делал: написал базовый скрипт на Playwright. Предположил что у карточек товаров есть атрибут data-sku — логично, многие сайты так делают.
Промпт AI: попросил написать базовый парсер на Playwright для Ozon с поиском по атрибуту data-sku.
Результат: total_checked: 0 на всех запросах. Селектор [data-sku] не существует на Ozon.
Почему не сработало: не проверил реальную структуру HTML перед написанием кода. Предположение оказалось неверным.

Попытка 2 — Playwright + playwright-stealth
Что делал: добавил playwright-stealth для маскировки браузера. Думал что проблема в блокировке, а не в селекторе.
Промпт AI: попросил добавить stealth режим и исправить селектор на основе реального HTML (скинул скриншот DevTools).
Что узнал из DevTools: зашёл на ozon.ru/search вручную, через Ctrl+Shift+C нашёл что ссылки на товары выглядят так:
/product/naushniki-...-1403391454/?at=...
SKU находится в конце URL перед /?. Это стало ключевым открытием.
Результат: ошибка ImportError: cannot import name 'stealth_async' — в новой версии библиотеки другое API. Потратил время на отладку импорта.
Почему не сработало: версия playwright-stealth изменила API, документация устарела. Даже после исправления импорта — Ozon всё равно блокировал через антибот challenge.

Попытка 3 — requests через внутренний API Ozon
Что делал: нашёл внутренний API endpoint Ozon:
https://www.ozon.ru/api/entrypoint-api.bx/page/json/v2
Через браузер он возвращал JSON с товарами (видел "id":"2770320926" и список items).
Промпт AI: попросил написать парсер через requests используя этот API endpoint.
Результат: widgetStates: [] — пустой объект. Товары не приходят.
Почему не сработало: API требует специальные заголовки или cookies сессии которые генерирует браузер. Простой requests сессии недостаточно — Ozon проверяет подлинность запроса.
Вывод: без браузера парсить Ozon очень сложно, нужен реальный браузер.

Попытка 4 — nodriver
Что делал: после трёх неудач решил попробовать nodriver — современную альтернативу Playwright/Selenium. Управляет Chrome напрямую через CDP протокол без ChromeDriver.
Промпт AI: попросил переписать парсер на nodriver с правильным селектором a[href*="/product/"] и регуляркой для извлечения SKU из URL.
Результат: антибот пройден! Найдено 83-87 ссылок. Но новая проблема — ошибка 'NoneType' object is not callable при чтении атрибута href.
Почему: в nodriver API другое — нет метода get_attribute(), атрибуты читаются через link.attrs.get("href").
Исправил руками: заменил await link.get_attribute("href") на link.attrs.get("href", "").

Попытка 5 — отладка регулярки и дедупликация (финальная)
Проблема 1: регулярка -i-(\d+)/ не матчила URL — оказалось Ozon не использует паттерн -i- везде. SKU просто последнее число в пути перед /?.
Исправление: заменил на -(\d+)/\? — матчит последнее число перед параметрами.
Проблема 2: total_checked: 2 при 87 найденных ссылках — каждый товар дублируется (две ссылки на одну карточку с разными классами).
Исправление: добавил seen_skus = set() — пропускаем уже виденные SKU.
Результат: все 3 прогона успешны, позиции находятся корректно.

Тестовые SKU — взял из реальной выдачи Ozon

Главный вывод
Самая ценная часть — анализ реального HTML через DevTools. Без этого все попытки были основаны на предположениях. Как только увидел реальную структуру URL (-2770320926/?at=...) — решение стало очевидным.
AI хорошо помогает с шаблонным кодом и идеями инструментов, но реальную структуру сайта нужно смотреть руками.
