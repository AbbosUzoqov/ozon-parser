# Архитектура масштабируемого парсера позиций Ozon

## Задача

500 товаров × 20 запросов = 10 000 проверок в день.
Результаты в PostgreSQL. Алерт в Telegram если позиция упала ниже 50.
Сервис не должен блокироваться.

---

## Технологии и почему

**Celery + Redis** — очередь задач. Каждая проверка (1 товар × 1 запрос) это отдельная задача. Redis хранит очередь, Celery выполняет задачи параллельно. Это стандартное решение для фоновых задач в Python.

**nodriver** — управление браузером. Единственный инструмент который стабильно проходит антибот Ozon на практике (проверено в этом проекте). Альтернатива — платные API типа ScrapingBee или Oxylabs, но это дороже.

**PostgreSQL** — хранение результатов. Простая таблица: товар, запрос, позиция, дата. Можно строить графики изменения позиций со временем.

**Telegram Bot API** — алерты. Бесплатно, просто, достаточно для задачи.

**FastAPI** — REST API для управления: добавить товар, посмотреть историю позиций, запустить проверку вручную.

## Архитектура

```
Scheduler (cron / Celery Beat)
        │
        ▼
  Redis (очередь задач)
        │
   ┌────┴────┐
   ▼         ▼
Worker 1   Worker 2   ...до N воркеров
(nodriver) (nodriver)
   │         │
   └────┬────┘
        ▼
  PostgreSQL (результаты)
        │
        ▼
  Telegram Bot (алерты если позиция < 50)
        
  FastAPI (опционально — веб-интерфейс)
```

**Как работает:**
1. Celery Beat каждый день в 9:00 создаёт 10 000 задач в Redis
2. N воркеров параллельно берут задачи из очереди
3. Каждый воркер открывает браузер, проверяет позицию, сохраняет в PostgreSQL
4. Если позиция < 50 — отправляет алерт в Telegram
5. FastAPI позволяет смотреть историю и управлять списком товаров

## Устойчивость и антиблокировка

**Прокси-пул:**
- Минимум 50 резидентных прокси с ротацией
- Каждый воркер использует свой прокси
- После 10 запросов — смена прокси
- При блокировке IP — автоматическая замена

**Rate limiting:**
- Не более 1 запроса в 30 секунд с одного IP
- 10 000 запросов / 50 прокси = 200 запросов на прокси в день
- 200 запросов × 30 секунд = ~100 минут нагрузки на прокси — безопасно

**Retry логика:**
- При ошибке или блокировке — повтор через 5 минут с другим прокси
- Максимум 3 попытки на задачу
- После 3 неудач — запись в лог и уведомление администратора

**Расписание:**
- Проверки распределены равномерно в течение дня (не все сразу)
- Ночью интенсивность меньше

## Риски и снижение

| Риск | Вероятность | Решение |
|------|-------------|---------|
| Ozon обновит антибот | Высокая | Мониторинг, быстрое обновление парсера |
| Прокси заблокируют | Средняя | Резервный пул, автоматическая ротация |
| Ozon изменит структуру HTML | Средняя | Алерт если total_checked = 0 на нескольких задачах подряд |
| Сервер упадёт | Низкая | Задачи в Redis сохраняются, воркеры перезапускаются автоматически |
| Большая нагрузка на БД | Низкая | Индексы на (sku, query, date), партиционирование по дате |

## Примерный бюджет в месяц

| Компонент | Цена |
|-----------|------|
| VPS сервер (2 CPU, 4GB RAM) для воркеров | ~$20/мес |
| VPS для PostgreSQL + Redis + FastAPI | ~$10/мес |
| Резидентные прокси (50 IP, ~5GB трафика) | ~$50/мес |
| Итого | **~$80/мес** |

**Оптимизация бюджета:** если бюджет ограничен — использовать датацентровые прокси вместо резидентных (~$15/мес), но выше риск блокировок. Итого от ~$45/мес.
